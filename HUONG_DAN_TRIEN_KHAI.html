Cơ sở của tài liệu. Nội dung dựa trên README, driveSync.js, package.json, vite.config.js, app.py trong D:\_QLCV_Merged. Các màn hình của GitHub, Google Cloud, Google Drive for Desktop thay đổi giao diện khá thường xuyên; hình minh họa trong tài liệu là mô phỏng, tên nút thực tế có thể lệch đôi chút.

Phạm vi. Các bước 1–5 trong README (sửa app.py, gộp dữ liệu, giao diện gộp, dọn lỗi) là phần Claude sẽ viết mã. Tài liệu này chỉ lo phần bạn phải tự thao tác.

Phần 2

Chuẩn bị máy và quyết định trước khi bắt đầu

2.1. Kiểm tra công cụ

Mở PowerShell (Win + X → Terminal) và chạy:

PowerShell
git --version
node -v
python --version

Máy hiện tại đã có Git 2.56, Node 24.12, Python 3.12. Nếu máy khác báo lỗi, cài tại git-scm.com, nodejs.org, python.org (khi cài Python nhớ tick Add Python to PATH).

2.2. Ba câu hỏi cần trả lời trước

  1. Tài khoản GitHub nào sẽ dùng? Hiện package.json trỏ tới github.com/lyannha2312/qlcv. Nếu đó chính là tài khoản của bạn, giữ nguyên. Nếu bạn dùng tài khoản khác (ví dụ gắn với thienan1204@gmail.com), phải đổi 2 chỗ trong package.json (homepage và deploy) và thêm origin mới ở Phần 5. Hãy báo cho Claude tên đăng nhập GitHub của bạn.
  2. Có giữ Client ID Google cũ không? Client ID đang nằm ở dòng 1 của driveSync.js (127705182868-…). Nếu bạn vẫn đăng nhập được vào dự án Google Cloud tạo ra nó, giữ lại (xem cảnh báo ở Phần 5.4). Chỉ tạo mới nếu không còn truy cập được.
  3. Máy nào sẽ chạy Flask? Chỉ nên có một máy chạy app.py và ghi dữ liệu tại một thời điểm. Drive đồng bộ file, nhưng không giải quyết xung đột khi hai máy cùng sửa dossiers.json.

Tạo kho GitHub và đẩy mã lên

Chạy lần lượt từng lệnh trong PowerShell. Dòng cuối của khối thứ hai là bước kiểm tra bắt buộc.

Kết quả đúng: lệnh Select-String cuối cùng không in ra dòng nào. Nếu thấy dòng chứa ho-so, dossiers hoặc backups, dừng lại, chạy git rm -r --cached . rồi kiểm tra lại .gitignore và git add . lần nữa.

Lần đầu đẩy, Git for Windows mở cửa sổ trình duyệt để bạn đăng nhập GitHub; bấm Authorize. Nếu không hiện, tạo Personal Access Token tại GitHub → Settings → Developer settings → Personal access tokens với quyền repo, dùng token thay mật khẩu.

3.4. Kiểm tra

Tải lại trang kho trên GitHub: phải thấy thư mục backend, frontend, file README.md, biểu tượng ổ khóa cạnh tên kho (Private) và không thấy backend/static/ho-so.

3.5. Bản web GitHub Pages: địa chỉ mới lyannha2312.github.io/tlcv/

Bản web chỉ xem hồ sơ, nhiệm vụ được phục vụ từ chính kho tlcv (nhánh gh-pages). package.json và vite.config.js đã trỏ sang tlcv. Kho qlcv cũ không còn dùng nữa.

GitHub Pages của tài khoản miễn phí chỉ chạy từ kho công khai, nên kho tlcv phải để Public. Mã nguồn sẽ đọc được công khai, kể cả mật khẩu APP_PASSWORD trong security.js (vốn đã nằm sẵn trong bản web, chỉ là chốt chặn thao tác nhầm, không phải bảo mật thật). Hồ sơ, dossiers.json, các bản sao lưu và config.json không lên GitHub nhờ .gitignore. Không bao giờ commit file client_secret*.json.

  1. Đổi kho sang Public: github.com/lyannha2312/tlcv → Settings → kéo xuống Danger Zone → Change repository visibility → Make public, nhập tên kho để xác nhận.
  2. Build và đẩy bản web: cd D:\_QLCV_Merged\frontend, npm install (lần đầu), rồi npm run deploy.
  3. Bật Pages: kho tlcv → Settings → Pages → Source: Deploy from a branch → nhánh gh-pages, thư mục / (root) → Save.
  4. Mở https://lyannha2312.github.io/tlcv/ (chờ 1–2 phút sau khi Save).

Origin https://lyannha2312.github.io đã khai báo ở Google Cloud, nên nút "Lưu lên / Tải từ Drive" dùng được ngay. Bản build cho Flask sẽ cần base khác (/); Claude sẽ tách hai chế độ build ở bước 4 của README.

Đã chọn: giữ nguyên D:\ho-so và nhờ Drive for Desktop đồng bộ chính thư mục đó (mục Folders from your computer). Không chép, không đổi đường dẫn, không đổi chế độ Stream hiện tại của tài khoản. config.json đã trỏ sẵn tới D:/ho-so.

D:\ho-so là dữ liệu đang dùng thật. Sao lưu trước khi bật đồng bộ và khi mở Flask lần đầu. Từ lúc bật đồng bộ, mọi thay đổi trong thư mục (kể cả xóa file bằng nút ✕, đổi tên, di chuyển do đổi Lĩnh vực) sẽ được đẩy lên Drive theo.

Phần 5

Cấp quyền Google cho nút "Lưu lên / Tải từ Drive"

Phần này dùng đăng nhập OAuth của Google (thư viện Google Identity Services trong driveSync.js) với quyền drive.file: ứng dụng chỉ thấy file do chính nó tạo ra, không đọc được phần còn lại của Drive.

Cảnh báo quan trọng về Client ID mới. Với quyền drive.file, file QLCV_Cloud_Backup.json chỉ hiện với đúng Client ID đã tạo ra nó. Nếu bạn tạo Client ID mới, nút "Tải từ Drive" sẽ không thấy bản backup cũ. Cách xử lý: trước khi đổi, dùng bản cũ Xuất JSON ra máy, sau đó nhập lại vào bản mới và bấm "Lưu lên Drive" để tạo file mới.

5.1. Xác định dự án Google Cloud đang giữ Client ID cũ

  1. Vào console.cloud.google.com, đăng nhập tài khoản đã tạo Client ID.
  2. Bấm bộ chọn dự án trên thanh đầu trang, chọn dự án phù hợp.
  3. Mở APIs & Services → Credentials, tìm dòng OAuth 2.0 Client IDs có mã bắt đầu bằng 127705182868-. Thấy là đang truy cập đúng dự án. Không thấy: chuyển sang 5.2 để tạo mới.

5.2. (Chỉ khi cần tạo mới) Tạo dự án và bật Drive API

  1. Tạo dự án: bộ chọn dự án → New project → đặt tên QLCV → Create.
  2. Bật Drive API: APIs & Services → Library → tìm "Google Drive API" → Enable.
  3. Cấu hình màn hình đồng ý (menu hiện nay tên Google Auth Platform, trước đây là OAuth consent screen):
    • App name: QLCV; User support email và Developer contact: email của bạn.
    • Audience / User type: External.
    • Mục Data Access / Scopes: thêm .../auth/drive.file.
    • Nếu để trạng thái Testing: thêm chính email bạn vào Test users, nếu không sẽ bị chặn "Access blocked". Muốn bỏ giới hạn này, bấm Publish app (quyền drive.file không thuộc nhóm nhạy cảm nên thường không cần xét duyệt).

5.3. Khai báo Authorized JavaScript origins

Đây là chỗ bắt buộc phải làm cho bản nâng cấp, vì giao diện sẽ chạy ở địa chỉ mới localhost:5001 do Flask phục vụ. Thiếu origin sẽ gặp lỗi origin_mismatch khi bấm nút.

  1. Vào Credentials → bấm tên Client ID (biểu tượng bút chì) → mục Authorized JavaScript origins → Add URI.
  2. Thêm các origin như bảng dưới.
    Edit OAuth client ID — Web application
    Authorized JavaScript origins
    http://localhost:5001
    http://localhost:5173
    https://TEN_GITHUB.github.io
    Authorized redirect URIs
    (để trống — không cần)
    Save
  3. Bấm Save, chờ vài phút (Google ghi chú có thể mất đến vài giờ để hiệu lực, thường chỉ vài phút).
OriginDùng khi

Phải truy cập bằng localhost, không dùng địa chỉ IP (ví dụ 192.168.x.x:5001). Google không chấp nhận origin IP thô qua http, nên nút Drive sẽ lỗi nếu mở từ máy khác trong mạng LAN.

5.4. Tạo Client ID mới (chỉ khi không giữ được cái cũ)

  1. Credentials → Create credentials → OAuth client ID.
  2. Application type: Web application; đặt tên QLCV web; thêm 3 origin ở mục 5.3; bấm Create.
  3. Sao chép Client ID (dạng …apps.googleusercontent.com). Không cần Client Secret.
  4. Dán vào dòng 1 của frontend\driveSync.js thay cho giá trị cũ, hoặc gửi cho Claude để thay. Client ID không phải bí mật nên để trong mã là bình thường.

5.5. Thử nghiệm nút Drive

  1. Mở ứng dụng ở http://localhost:5001 (sau khi bản gộp hoàn thành) hoặc http://localhost:5173 khi chạy npm run dev.
  2. Bấm Lưu lên Drive, nhập mật khẩu xác nhận (security.js), chọn tài khoản Google, bấm Allow ở màn hình cấp quyền.
  3. Vào drive.google.com, thư mục gốc My Drive phải có file QLCV_Cloud_Backup.json.
  4. Thử bấm Tải từ Drive để chắc chắn đọc lại được.

Phần 6

Chạy thử và danh sách kiểm tra cuối

6.1. Chạy thử hiện tại (trước khi có bản gộp)

Hiện hai phần vẫn chạy riêng. Để kiểm tra môi trường trên máy mới:

PowerShell
# Giao diện QLCV (dev)
cd D:\_QLCV_Merged\frontend
npm install
npm run start        # vite (5173) + server.js mở thư mục (3001)

# Kho hồ sơ Flask — mở cửa sổ khác
cd D:\_QLCV_Merged\backend
.\Mo_KhoHoSo.bat     # tự tạo venv, mở http://localhost:5001

Lần đầu npm install cần Internet vì thư viện xlsx tải từ cdn.sheetjs.com. Thư mục node_modules, dist, venv chưa được chép sang bản gộp nên bước này là bắt buộc.
